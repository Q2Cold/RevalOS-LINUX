# История сборки KDE для Reval OS

Снимок сценариев из рабочей виртуальной машины.
База: LFS с systemd. Qt 6.11.2, Frameworks 6.29.0,
Plasma 6.7.4, Konsole и Dolphin 26.04.3.
Nix используется отдельно для приложений.

Это архив разработки, а не универсальный установщик.
Полная сборка с нуля по этому набору пока не проверена.

## Содержимое

- kde/run-frameworks.sh и kde/run-plasma.sh — групповые сборщики.
- kde/as-myos.py — запуск команд сборки от пользователя myos.
- kde/frameworks-6.29.0 и kde/plasma-6.7.4 — списки пакетов.
- kde/install-*.sh — зависимости, приложения и исправления.
- kde/build-*-group.sh — ранние сценарии с отдельными запросами пароля.
- fix-runtime-dir.py — исправление конкретной строки /etc/profile.

## Ограничения

- Пути /home/myos/reval-build, /opt/qt6 и пользователь myos заданы явно.
- as-myos.py требует существующий каталог frameworks-6.29.0.
- run-frameworks.sh предполагает наличие каталога completed.
- Некоторые install-сценарии автоматически запускают следующую группу.
- install-qtbase-cups.sh останавливает LightDM и требует уже собранный Qt.
- add-fuse-kernel.sh содержит PARTUUID диска исходной виртуалки.
  На другом диске этот идентификатор использовать нельзя.
- install-plasma-nm.sh содержит оставшийся параметр
  DISABLE_MODEMMANAGER_SUPPORT; он не устранил зависимость.
  Для рабочей сборки были установлены ModemManager и ModemManagerQt.
- В наборе нет полного первоначального рецепта Qt и всех зависимостей.
- Маркеры completed не заменяют проверку установленных файлов.
- MD5 сохранены из исходных рецептов; это не подписи поставщиков.

## Проверка архива

Проверены синтаксис Bash/Python и формат списков MD5.
Сценарии при проверке не запускались.
Рабочие настройки сеанса находятся отдельно в reval/overlay,
конфигурация ядра — в reval/kernel.
